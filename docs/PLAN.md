# Claude Control Room — แผนสร้าง

เขียน 2026-11-23 · สถานะ: รอสั่ง `go` · mockup ที่อนุมัติแล้ว (ธีมดำขาว):

## 1. เป้าหมาย

เว็บในเครื่องนี้ หน้าเดียว ใช้ดูและสั่งงาน Claude ทุก session โดยไม่เปลี่ยนวิธีทำงานเดิม
(กฎแบ่งงานใน CLAUDE.md, handoff, Notion, wiki ใช้ต่อทั้งหมด)

ของที่ต้องมี (ตาม mockup):

1. โครงข่ายงาน: เครื่อง → session → subagent มีเส้นเชื่อม ทุกกล่องมีข้อความว่ากำลังทำอะไร
2. Widget ย้ายได้ ปรับขนาดได้ จำ layout ทั้งหน้าไม่ต้องเลื่อน มี layout สำเร็จรูป
3. ช่องดูงาน 2 ช่อง + แชทเต็มจอ สั่งงานเพิ่มได้ตลอด
4. สลับโมเดลและ effort รายงาน
5. คำถามจาก Claude เด้งเป็น popup ตอบด้วยปุ่มหรือพิมพ์
6. ผู้ช่วยสรุป (Haiku อ่านอย่างเดียว)
7. บันทึกงาน: สรุปสั้น + สิ่งที่ไม่เวิร์ก ทุกครั้งที่งานจบ
8. Clip Studio: หัวข้อ → ค่าปรับ → สไตล์ (ของเรา + Lemo-Opuscar) → โมเดล → เสียง ElevenLabs → สร้าง
9. ตัวละคร Claude ขยับตามสถานะจริง

(1) thinking ถ้ามี (2) คำอธิบายของ tool ที่กำลังรัน (3) ข้อความล่าสุดของ Claude

## 3. โครงสร้าง

```
browser (React)  ⇄  WebSocket  ⇄  server (Node, ฟังที่ 127.0.0.1 เท่านั้น)
                                    ├─ Watcher   อ่าน sessions/*.json + transcript ทั้งเครื่อง (อ่านอย่างเดียว)
                                    ├─ Runner    เปิด/คุม session ที่เริ่มจากเว็บ (claude -p stream-json)
                                    ├─ Asker     จับคำถาม/คำขออนุญาต ส่งขึ้น popup แล้วส่งคำตอบกลับ
                                    ├─ Observer  ผู้ช่วยสรุป (claude -p --model haiku ไม่มีสิทธิ์แก้ไฟล์)
                                    ├─ Worklog   เก็บ error จาก stream + สรุปสั้นตอนจบงาน
                                    ├─ Clips     คิวงานคลิป + ตัวอย่างเสียง
                                    └─ SQLite    layout, บันทึกงาน, คิวคลิป, voice ID
```

- โฟลเดอร์: `C:\Users\<you>\claude-control-room` (git ในเครื่อง ยังไม่ผูก remote จนกว่าจะสั่ง)
- Server: Node + TypeScript, `node:sqlite`, `ws`
- หน้าเว็บ: React + Vite, ฟอนต์ IBM Plex Sans Thai / IBM Plex Mono, ธีมดำขาวตาม mockup
- ใช้ subscription เดิมผ่าน `claude` CLI ไม่มี API key ของ Anthropic
- Secret (ElevenLabs, TokenMe): `secrets get <name>` ตอนรัน ไม่เขียนลงไฟล์

## 4. เรื่องที่ยังไม่รู้ ต้องทดลองก่อน (ขั้น 0)

| # | คำถาม | ถ้าได้ | ถ้าไม่ได้ |
|---|---|---|---|
| S1 | ส่งคำสั่งเข้า session ที่เปิดใน terminal ผ่าน `messagingSocketPath` ได้ไหม | สั่งงานได้ทุก session | session จาก terminal ดูได้อย่างเดียว มีปุ่ม "ย้ายมาคุมจากเว็บ" (`--resume`) |
| S2 | คำถามแบบมีตัวเลือก (AskUserQuestion) ในโหมด stream-json ออกมาในรูปไหน | popup ตอบด้วยปุ่ม ก/ข/ค | แสดงคำถามเป็นข้อความ ตอบด้วยการพิมพ์ |
| S3 | สลับโมเดล/effort กลาง session ที่รันอยู่ได้ไหม | สลับทันที | จบ turn แล้วเปิดต่อด้วย `--resume` + โมเดลใหม่ (ช้ากว่าไม่กี่วินาที) |
| S4 | รันงานด้วยโมเดล TokenMe/AIpass | ใช้ตัวครอบที่มีอยู่ (`ds-agent`, `claude-9arm`) เป็น runner | โมเดลพวกนี้ใช้ได้เฉพาะงานเขียนบท/สรุป |
| S5 | key ElevenLabs ใน vault ดึงรายชื่อเสียงได้ไหม (ที่จดไว้คือใช้ได้เฉพาะ TTS) | มีรายการเสียงให้เลือก | ใส่ voice ID เอง (เริ่มจาก 3 ตัวที่มี) |

แต่ละข้อทำเป็นสคริปต์ทดลองสั้นๆ ผลจดลง `docs/spikes.md` ก่อนเริ่มขั้น 1

## 5. ขั้นสร้าง

ทุกขั้นจบด้วยของที่เปิดใช้ได้จริง

### ขั้น 1 — ดูอย่างเดียว
- Watcher: ไล่ `sessions/*.json`, ตาม transcript แบบสด, อ่าน subagent
- หน้าโครงข่าย + ข้อความในกล่อง + สีสถานะ (กำลังทำ / รอคุณ / ว่าง / เสร็จ)
- Widget ย้าย/ปรับขนาด/จำ layout + layout สำเร็จรูป 3 แบบ
- ช่องดูงาน 2 ช่อง (ยังสั่งไม่ได้)
- **ผ่านเมื่อ:** เปิด session ใน terminal 3 ตัว แล้วเว็บแสดงครบ ชื่อ โมเดล subagent ตรงกับของจริง และอัปเดตภายใน 2 วินาที

### ขั้น 2 — สั่งงาน
- Runner: เปิดงานใหม่ (โฟลเดอร์, โมเดล, effort, คำสั่ง), สั่งเพิ่มระหว่างทำ, หยุด
- แชทเต็มจอ, ปุ่มคำสั่งด่วน (`ทำงานต่อ`, `go`, `เสร็จยัง`, `handoff`, `commit push`)
- สลับโมเดล/effort ตามผล S3
- **ผ่านเมื่อ:** เปิดงานจากเว็บ สั่งเพิ่ม 2 ครั้งระหว่างทำ เปลี่ยน effort แล้วงานเดินต่อ และ session เดียวกันเปิดต่อใน terminal ด้วย `claude --resume` ได้

### ขั้น 3 — คำถามเด้ง
- Asker: คำถามและคำขออนุญาตขึ้น popup + แจ้งเตือน Windows + ป้ายนับที่หัวหน้าเว็บ
- คำตอบส่งกลับเข้า session
- **ผ่านเมื่อ:** งานที่ถามคำถาม เด้งภายใน 2 วินาที ตอบด้วยปุ่มแล้วงานเดินต่อ

### ขั้น 4 — ผู้ช่วยสรุป + บันทึกงาน
- Observer: Haiku ได้ข้อมูลย่อของทุก session ตอบ "เสร็จยัง / มีอะไรรอฉัน / สรุปงานวันนี้"
- Worklog สองชั้น:
  - ชั้นแน่นอน: server เก็บทุก tool ที่ error จาก stream เอง ไม่พึ่งโมเดล
  - ชั้นสรุป: ตอนงานจบ ตัวหลักเขียนสรุป 1 บรรทัด + รายการที่ไม่เวิร์ก ไม่มีความเห็น
- **ผ่านเมื่อ:** งานที่มี error 2 ครั้ง จบแล้วมีบันทึกครบทั้ง 2 รายการโดยไม่ต้องสั่ง

### ขั้น 5 — Clip Studio
- ตรวจ repo Lemo-Opuscar ก่อน แล้วติดตั้ง ดึงรายชื่อสไตล์ + ภาพนิ่งของแต่ละสไตล์
- ฟอร์มตาม mockup → สร้างเป็น session งานคลิป ใช้ workflow คลิปเดิม
- ขั้นของงาน: บท → storyboard → สร้าง scene → preview → **พร้อม render แล้วหยุดรอสั่ง** (กฎเดิม)
- เสียง: ElevenLabs `eleven_v3` เลือก voice ID, ปุ่มลองฟังสร้างเสียงสั้นแล้วเก็บ cache ตาม (เสียง + ประโยค)
- งานคลิปขึ้นใน Control Room ทั้งใน widget และในโครงข่าย
- **ผ่านเมื่อ:** สร้างคลิป 30 วิ 1 ตัวจากหน้าเว็บจนถึง "พร้อม render" และลองฟังเสียงได้ 3 ตัว

### ขั้น 6 — ตัวละคร + เก็บงาน
- ตัวละครขยับตามสถานะจริง (ทำงาน / มีคำถาม / เสร็จ)
- เปิดเองตอน Windows logon, ไอคอนถาด
- ต่อกับ control center ของ dot-agent (เข้าจากเครื่องอื่นผ่าน Tailscale + PIN) — ทำเมื่อสั่ง

## 7. ความเสี่ยง

- **ไฟล์ภายในของ Claude Code เปลี่ยนรูปแบบได้ตอนอัปเดต** (sessions/*.json, transcript) → Watcher แยกเป็นชั้นเดียว มี test กับไฟล์ตัวอย่าง และแสดง "อ่านไม่ได้" แทนการเดา
- **โควตา:** ผู้ช่วยสรุปใช้ Haiku และเรียกเมื่อถามเท่านั้น ไม่วนถามเอง · แถบโควตาบนหัวเว็บใช้ค่าจาก statusline เดิม
- **สั่งผิด session:** ทุกช่องส่งคำสั่งแสดงชื่องานและโฟลเดอร์ติดกับปุ่มส่ง
- **เข้าจากเครื่องอื่น:** ขั้น 1–5 ฟังเฉพาะ 127.0.0.1
